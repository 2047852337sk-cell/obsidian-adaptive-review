# Obsidian Adaptive Review · 自适应间隔复习

把知识写成可回忆的问题，在 Obsidian 里完成「回忆 → 核对 → 纠错 → 评分 → 下次复习」。

这是从日常使用的笔记库提取的 **DataviewJS + Templater 工作流**。它包含模板、评分控件、复习总表、未来预览、诊断面板和归档页，可按自己的学科组织卡片。首发版 `0.1.0`，MIT 开源。

## 功能

- **主动回忆 + 费曼讲解**：六个问题、默认折叠答案；轻量模式完成 Q1～Q3、Q6，完整模式完成 Q1～Q6。
- **四级评分**：按实际评分日期调整下次安排，每次保留漏洞、纠正和调度历史。
- **每日总表**：到期、逾期、未来安排和阶段进度。
- **诊断与复盘**：薄弱知识点、本周统计、按学科和周期整理分析材料。
- **完成与重启**：完成最后阶段后进入归档视图，保留历史开始下一轮。
- **本地数据**：评分保存在 Markdown 属性和正文中。分析材料由你手动复制到选择的 LLM；系统不包含模型密钥，也不会自动发送笔记。

```mermaid
flowchart LR
    A[从模板创建卡片] --> B[打开今日复习]
    B --> C[先回忆，再核对答案]
    C --> D[填写漏洞与纠正]
    D --> E[评分 1—4]
    E --> F[写入历史和下次日期]
    F --> B
    E --> G[最后阶段通过 → 归档]
```

## 五分钟开始

1. 在 GitHub 仓库点击 **Code → Download ZIP** 并解压。
2. 在 Obsidian 中选择 **打开本地仓库**，打开解压目录中的 **`vault` 子文件夹**，不要打开下载包的最外层。
3. 在设置 → 第三方插件中安装并启用 **Dataview** 和 **Templater**。下载包不附带第三方插件程序。
4. 在 Dataview 设置中启用 **Enable JavaScript Queries**。
5. 在 Templater 设置中把 **Template folder location** 设为 `模板`。
6. 在设置 → 外观 → CSS 代码片段中启用 `review-dashboard`、`review-card-refined`。
7. 打开 `开始使用`，从示例卡和复习总表开始。

示例是专门编写的演示内容，固定初始日期为 `2026-01-01`，显示逾期是正常现象。评分会从当天重新安排。正式使用前可以删除示例，或复制整个 `vault` 到一个不受 Git 管理的位置再开始学习。

**新增卡片**：命令面板 → `Templater: Create new note from template` → `间隔复习模板`。填写 `分类`（学科）、Q1～Q6 和答案。可以新增 `子分类` 属性；未填写时，面板采用卡片的直接父文件夹名称。卡片保留 `复习/待复习` 标签才能被总表发现。模板中的 `<% ... %>` 必须由 Templater 执行，直接复制模板文字不会自动生成日期。

## 装进已有笔记库

先备份，再将 `vault/复习/系统`、两张复习页面和 `vault/模板/间隔复习模板.md` 按原相对路径复制到你的库。复制两个 CSS 文件到已有库的 `.obsidian/snippets`，再手动启用；**不需要覆盖已有库的 `.obsidian/appearance.json`**。

同名文件已存在时先比较内容，不要整目录覆盖。当前版本依赖 `模板/间隔复习模板.md` 与 `复习/系统/...` 的路径，移动系统目录需要同步修改 `dv.view(...)` 和模板排除条件。

## 评分如何安排日期

阶段依次为 D0、D1、D3、D7、D14、D30、D60，正常推进的相邻间隔为 1、2、4、7、16、30 天。它们是基准阶段标签；实际日期始终以 `下次复习日` 为准。

| 评分 | 含义 | 调度 |
|---|---|---|
| 1 | 完全不会 | 次日回到 D0，轮次加 1，完整复习 |
| 2 | 不完整 | 停留当前阶段，2 天后完整加测 |
| 3 | 基本掌握 | 进入下一阶段，使用标准间隔，连续熟练次数清零 |
| 4 | 熟练掌握 | 进入下一阶段；连续至少两次评分 4 时，间隔乘 1.25 向上取整，上限 45 天 |

D60 评分为 3 或 4 时标记完成。D0、D7、D60 默认完整复习，其他阶段默认轻量复习，低分会强制完整复习。提前或逾期评分都从**实际评分当天**计算，连续高分只延长间隔，不跳过阶段。同日再次评分会弹出提醒，确认后仍会追加记录。

这是一套透明、可修改的经验规则，并未实现 FSRS 或 SM-2，也不根据个人记忆曲线拟合参数。评分用于记录当次回忆表现。

## 诊断与分析

最近三次评分中至少两次为 1 或 2，会进入薄弱项列表。诊断不修改调度。分析面板支持本周、本月、累计至今，以及学科和子分类筛选，可以复制证据和提示词，也可以创建本地分析记录。

分析材料可能包含你后续填写的私人卡片名称、漏洞与纠正；复制给外部 LLM 前自行检查。原始示例库不包含任何个人学习记录。

原工作流的英语语法目录补齐功能保留为可选项，默认关闭。若确实沿用该目录，可把总表中的诊断调用改为：

```js
await dv.view("复习/系统/复习诊断面板", {
  grammarPrefix: "复习/英语语法复习/"
});
```

启用后，该目录下漏标签的卡也会被发现，补齐按钮会写入 `分类: 英语语法` 和复习标签。其他学科无需设置此项。

## 常见问题

- **看到代码或没有按钮**：安装并启用 Dataview、启用 JavaScript Queries，在阅读视图打开卡片。实时预览需把光标移出代码块。GitHub 的 Markdown 预览不会执行脚本。
- **Custom view not found**：确认打开的是 `vault`，系统目录未改名；Windows 应打开 UTF-8 中文路径对应的真实文件。
- **总表没有卡片**：检查 `复习/待复习` 标签、有效日期、`调度类型: 自适应`；等 Dataview 更新索引后重新打开页面。
- **归档没有移动文件**：归档是按状态筛选的视图，卡片仍留在原目录。
- **误评分**：先使用 Obsidian 文件恢复或备份恢复整张卡。当前没有专门的撤销按钮；只改日期会留下不一致的历史。
- **多个设备同时评分**：一次只在一台设备操作同一张卡，等待同步完成。当前读写流程没有跨设备事务锁。
- **旧复选框卡**：总表、归档和未来预览保留兼容读取；诊断面板仍按自适应格式检查，会提示缺字段。不要把诊断提示当作自动迁移。

## 兼容性与开发

源环境观察到 Dataview `0.5.68`、Templater `2.25.0`；这是版本记录，不是对所有插件版本或移动端的兼容保证。发布验证分为代码/数据自动检查与 Obsidian 实机检查，详见 [验证说明](docs/VALIDATION.md)。

普通使用不需要 Node.js。开发者使用 Node.js 20+ 执行：

```sh
npm test
npm run check
```

目录：`vault/` 是可打开的示例库，`tests/` 验证调度和写入行为，`scripts/` 做结构与发布文件检查。贡献方法见 [CONTRIBUTING.md](CONTRIBUTING.md)，更新见 [CHANGELOG.md](CHANGELOG.md)。
